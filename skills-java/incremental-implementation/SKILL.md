# 增量实现

## 概览

使用小的、可验证的薄垂直切片实现功能。一次一个切片——实现、测试、验证、提交。每个切片都通过整个栈，使得功能随时可用和可测试。

## 何时使用

- 任何影响多个文件的变更
- 实现新功能时
- 进行重大重构时
- 用户要求增量构建时

## 何时不使用

- 单一文件的简单修复（拼写错误、变量重命名）
- 用户明确要求快速/草稿原型且接受无增量的权衡时（记录此决定）

## 薄垂直切片

每个切片都通过整个栈——从 UI 到数据库。切片足够小，可以一次完成和验证。

```
好：添加任务创建（端点 + 验证 + 测试 + UI）
避免：添加所有后端端点，然后稍后添加 UI
```

## 实现过程

### 第 1 步：识别第一个切片

从规格中选择第一个可验证的切片。它应该：
- 足够小，可以一次完成
- 通过整个栈（UI 到数据库）
- 独立可测试
- 为用户增加价值

```markdown
第一个切片：用户可以创建单个任务
- 端点：POST /api/tasks
- 验证：title 非空
- 数据库：插入任务记录
- UI：创建表单
- 测试：端到端验证
```

### 第 2 步：实现切片

实现整个栈的切片：

```
1. 编写测试（应该失败）
2. 实现最小代码以使测试通过
3. 运行测试（现在应该通过）
4. 运行构建和 lint
5. 提交："feat: 添加任务创建"
```

### 第 3 步：验证

在继续下一个切片之前验证：
- [ ] 所有测试通过（`mvn test`）
- [ ] 构建成功（`mvn clean package`）
- [ ] Lint 通过（`mvn spotless:check`）
- [ ] 手动测试切片（如适用）

### 第 4 步：重复

选择下一个切片并重复。每个切片都构建在前一个切片之上。

```markdown
切片 1：创建任务 ✓
切片 2：列出任务
切片 3：更新任务
切片 4：删除任务
切片 5：过滤任务
```

## 特性标志

对于可能影响现有用户的大变更，使用特性标志：

```java
// Spring Boot 特性标志
@Component
public class FeatureFlags {
    @Value("${feature.new-task-flow:false}")
    private boolean newTaskFlow;

    public boolean isNewTaskFlowEnabled() {
        return newTaskFlow;
    }
}
```

**规则：**
- 在实现开始时就设置特性标志
- 默认关闭，直到准备好
- 在 CI 中测试两种状态（开启和关闭）
- 在全面推出后 2 周内清理

## 安全默认值

当不确定时，选择更安全的默认值：

```java
// 好：默认严格，可以放宽
private static final int MAX_RETRIES = Integer.getInteger("max.retries", 3);

// 避免：默认宽松，可以收紧
private static final int MAX_RETRIES = Integer.getInteger("max.retries", 100);
```

## 可回滚的变更

使每个切片都可回滚：
- 数据库迁移应该有回滚脚本（Flyway/Liquibase）
- API 变更应该向后兼容
- UI 变更应该通过特性标志控制

```bash
# 如果切片出现问题，回滚到上一个已知良好状态
git revert HEAD
```

## 提交策略

每个切片都是一个原子提交：

```
feat: 添加任务创建端点和验证
feat: 添加任务列表端点
feat: 添加任务更新端点
feat: 添加任务删除端点
feat: 添加任务过滤功能
```

## 常见合理化

| 合理化 | 现实 |
|---|---|
| "我会一次性构建整个功能" | 大变更更难审查、测试和回滚。增量构建降低风险。 |
| "第一个切片没有价值，因为功能不完整" | 每个切片都应该增加价值。如果它不增加价值，它太大了。 |
| "增量构建太慢了" | 增量构建使得问题更早显现。一次性构建在后期发现问题代价更高。 |
| "我可以跳过测试，稍后再加" | 没有测试的增量不是增量——它是赌博。测试即证明。 |

## 危险信号

- 切片大到需要多天完成
- 切片不通过整个栈（仅后端或仅 UI）
- 在继续前没有验证上一个切片
- 提交包含多个切片的工作
- 特性标志默认开启

## 验证

在实现完成后：

- [ ] 每个切片都有通过的测试（`mvn test`）
- [ ] 构建成功，无警告（`mvn clean package`）
- [ ] Lint 和格式检查通过（`mvn spotless:apply`）
- [ ] 每个切片都是原子提交
- [ ] 特性标志已清理（如适用）
- [ ] 功能随时可用和可测试
